# Architecture Decision Records

ADRs capture **significant, durable decisions** and their rationale.

## Process

1. Copy template below into `NNNN-title.md`.  
2. Status starts as `Proposed`.  
3. After review, mark `Accepted`, `Deprecated`, or `Superseded`.  
4. Update [decision-log.md](../07-risk-and-future/decision-log.md).  

## Template

```markdown
# ADR NNNN: Title

- Status: Proposed | Accepted | Deprecated | Superseded
- Date: YYYY-MM-DD
- Decision makers: ...

## Context
## Decision
## Consequences
## Alternatives considered
## Assumptions
```

## Rules

- ADRs are append-only; supersede rather than rewrite history.  
- Ethics-boundary ADRs require ethics reviewer.
